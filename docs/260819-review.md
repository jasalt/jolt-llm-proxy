## Already addressed

- **Structured logging:** adopted and used in `llm-proxy.core`, `llm-proxy.proxy`, and `llm-proxy.transport.ws`; `org.clojure/tools.logging` is pinned in `deps.edn`.
- **Property testing:** `test.check` is explicitly declared under the `:test` alias and used in both `test/codex/ws_test.clj` and `test/llm_proxy/generative_test.clj`.
- **Direct WebSocket coverage:** the review’s “almost no coverage” is now obsolete. `test/codex/ws_test.clj` covers:
  - lengths `0`, `1`, `125`, `126`, `65535`, `65536`;
  - partial reads;
  - generated frame/chunk boundaries;
  - fragmentation;
  - ping/pong;
  - close frames;
  - malformed control/data frames;
  - isolated pools, busy owners, idempotent release, and stale release.
- **Pool runtime isolation:** fixed. `codex.ws/make-pool` returns `{:sessions atom :lock Object :now-ms fn}`; `llm-proxy.core/start!` creates one per application instance. There is no longer a global `codex.ws/pool` or `pool-lock`.
- **Clock/random seams:** substantially addressed:
  - `llm-proxy.time/*now-ms*`;
  - `llm-proxy.id/*random-bytes*`;
  - injected `:now-ms` / `:random-hex` in startup;
  - injected `:now-ms` in pools;
  - injected `:http-post` in `codex.auth`.
- **CLI extensibility:** already adopted via `babashka/cli`, with ADR `260820B`.
- **README architecture:** it now explicitly lists `llm-proxy.schema`.
- **CI namespace loading:** `.github/workflows/test.yml` explicitly loads all current production namespaces, including schema and both transports.
- **Development nREPL:** already included and documented, though it is currently a normal dependency and optional runtime feature (`serve --nrepl`), rather than a development-only alias.
- **Centralized classified/redacted errors (completed, commits `96bfe31`, `45afd1b`):**
  - `llm-proxy.error` maps classified failures to stable, OpenAI-shaped public errors: input `400`, auth `401`, upstream HTTP `502`, timeout `504`, and unknown internal errors `500`.
  - HTTP and streaming paths no longer return raw exception messages. The mapper returns generic public text, while `log!` records only category, public code, upstream status, and explicitly selected safe context.
  - OAuth exchange/token failures are marked `:auth`; upstream SSE status failures remain `:upstream-http` without retaining an upstream body in exception data.
  - WebSocket setup/initial-write failures are marked `:ws-transport` and may fall back to SSE. Already classified failures, including auth failures, propagate without fallback.
  - Proxy tests cover public-message redaction and prove SSE fallback occurs for `:ws-transport` but not `:auth`.

## Still useful / worthwhile

### 1. Outbound WS-frame and handshake tests (completed)

`test/codex/ws_test.clj` now directly verifies:

- `write-frame` client masking, unmasking correctness, and all wire-length encodings at `125`, `126`, `65535`, and `65536` bytes;
- UTF-8 text-frame encoding and controlled concurrent writers, proving the write lock prevents overlap;
- case-insensitive upgrade-header lookup, `101` status validation, reject/close behavior for bad status or accept key, fixed handshake-header limit, and retention of bytes after `\r\n\r\n` as the first WebSocket frame.

The tests use the narrow `codex.ws/*tls-connect*` dynamic seam and an in-memory Jolt tagged-table stream; no live socket is opened. `dial` now requires a successful HTTP `101` upgrade status as well as a matching `Sec-WebSocket-Accept` value.

### 2. Complete dependency seams only where they buy deterministic behavior

The review is directionally right, but this is partly complete already. The remaining notable direct dependencies are:

- `codex.cli`: direct `http/get` / `http/post` for device login and usage;
- `codex.ws/dial`: direct TLS connection and time/random through leaf namespace functions.

CLI HTTP injection would make device-flow and usage tests much cleaner. I would **not** broadly turn every function into dependency-map plumbing yet; the existing narrow seams and dynamic leaf bindings are a reasonable balance.

### 3. Error/redaction tests (completed for boundary mapping)

Logger-capture coverage now binds the narrow `llm-proxy.error/*emit!*` sink and proves that a failure's token, session ID, authorization header, prompt, and raw upstream body are absent from the structured event. The captured event is limited to classification, public code, upstream status, and explicitly supplied safe request metadata.

Handler-level tests now verify stable, redacted mappings for upstream HTTP (`502`), auth (`401`), timeout (`504`), and unknown (`500`) failures. Future work here is limited to broader integration/streaming-path coverage rather than the central mapper.

## Defer / not worth doing now

- **Integrant:** no. `start!`/`stop!` is concise, explicit, tested, and currently owns only a few resources.
- **Reitit:** no. The current router is `ruuter`, and routes have grown beyond the review’s original “four exact matches” due to the optional dashboard, but not enough to justify a routing migration.
- **`crypto-equality`:** no. The existing equal-length check plus byte comparison is adequate for the single API-key boundary.
- **`ring-defaults`:** no. It would add browser/session/CSRF assumptions that are not useful for a JSON/SSE proxy.
- **Splitting `codex.ws` now:** defer. It is still the largest and mixed-responsibility namespace, but it is now well bounded, documented, and tested. Split opportunistically while extending handshake/frame tests or changing pool behavior—not as a standalone refactor.
- **Replacing collector `StringBuilder`s:** low priority. They are confined to request-owned accumulator state; document that ownership if desired, but immutable-string rewrites are unlikely to improve the service materially.
- **TUI/Datastar/general adjacent-app libraries:** the dashboard already provides the only operational visibility that seems justified. More UI/framework work is not a current proxy priority.
- **Formatter introduction:** harmless as check-only, but lower value than error handling and protocol tests.
- **clj-kondo:** useful eventually, but Jolt-specific FFI/shim behavior means it should begin informational-only. It is not an urgent correctness gap.
